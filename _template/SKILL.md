# Skill 标题

## 适用场景

在这里描述应触发该 Skill 的用户意图、任务类型或上下文。

## 不适用场景

在这里说明哪些相似任务不应该使用该 Skill。

## 输入

- 列出执行前需要从用户或项目中获得的信息。
- 缺少关键输入时，应先向用户确认，不要自行猜测。

## 工作流程

1. 检查任务上下文和约束。
2. 收集完成任务所需的最小信息。
3. 按领域要求执行任务。
4. 验证结果。
5. 向用户说明结果、风险和未完成事项。

## 输出

描述最终应产生的文件、报告、代码修改或答复形式。

## 完成条件

- [ ] 已满足用户目标。
- [ ] 已遵守相关 Rules。
- [ ] 已执行适用的验证。
- [ ] 已说明无法验证的部分。

## 参考资料

需要时在当前 Skill 目录创建 `references/`，并从此处使用相对路径引用。

## 示例

需要时在当前 Skill 目录创建 `examples/`，避免在入口文件中堆积大量示例。

## Agent 兼容说明

仅在确有必要时记录 Agent 专有差异；通用工作流不得依赖本节才能成立。
